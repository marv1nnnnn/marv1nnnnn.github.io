# Generated website content

Clin is the source of truth for all public website content. Site data under `content/` (excluding this README) and `data/shows.json` is generated by `pnpm sync:clin`; do not edit it directly.

Only Clin notes with the positive allowlist tag `site` are exported.

## Clin sources

| Vault path | Format | Generated output |
|---|---|---|
| `site/media/*.md` | Media body fields | `content/listening/items.json` |
| `site/journal/*.md` | Markdown cards | `content/journal/cards/*.md` |
| `site/projects/*.md` | Markdown cards | `content/projects/cards/*.md` |
| `site/data/*.txt` | JSON body | Signal metadata, About, Influences, Billboards, and Shows JSON |

### Media

Tags: `site`, `media`, and exactly one of `music`, `video`, `text`, `game`, `live`.

```text
Date: YYYY-MM-DD
Creator: Name
URL: https://example.com
```

`URL` is optional.

### Journal and Projects

Journal tags start with `site`, `journal`; project tags start with `site`, `project`. Additional tags are exported.

```text
Date: YYYY-MM-DD
Summary: Short summary
ID: stable-slug
Subtitle: Optional subtitle

Markdown body…
```

`Subtitle` is optional.

### Structured website data

Files under `site/data/*.txt` use the native tags `site` and `website-json`, followed by a JSON body. Their source and destination paths are explicitly allowlisted in `scripts/clin-content.js`.

Clin 0.8.32 does not preserve custom frontmatter fields, so structured fields remain in note bodies.

## Workflow

Before editing on any host:

```bash
clin-sync pull
```

After editing:

```bash
clin-sync
pnpm sync:clin
pnpm test:clin
pnpm build
```

Generated files remain checked in so CI can build without access to the private vault. The idempotent importer is `pnpm migrate:clin`.
